# SFM FX New Age

Local Debian/X11 Forex signal platform with four user workspaces and 42 stable backend view contracts.

## Current architecture

- PySide6 desktop shell.
- Typed in-process priority event router.
- Component registry and command allowlists.
- Projection store shared by all tab views.
- One human-initiated **Issue** path for creating new pending-order intent.
- SQLite WAL market/signal/configuration state, atomic order reservations, journal and restart reconciliation.
- Explicit fixture transport for no-network tests; optional cTrader SDK connector has real read-only account/quote/history acceptance and normal Desktop saved-login proof. A deliberately bounded real demo pending Issue/cancel proof is recorded in `PROGRESS.md`; it is not general permission to trade.
- Shared `TabApi` v1 for independently owned tab widgets, including command-capability discovery, dependency-aware snapshot subscriptions and consumer disposal.
- Broker/endpoint/account/origin-scoped market, signal, order and position records; append-only bar corrections preserve historical as-of results.
- Read-only position ingestion distinguishes unknown, incomplete and explicitly observed last-known snapshots; pending-order acceptance never implies a position.
- Calculator-derived dark navy/slate Qt theme, DejaVu Sans, compact cards and blue accents.
- Account class is broker metadata and does not gate application use.
- Shared causal analytical objects, bounded LogicTiles lifecycle, cached scanner scheduling, source-owned calendars/continuity/backfill and isolated replay. Unimplemented strategy methods remain explicitly unavailable.
- Headless Tab 3 producer/recipe installation and human-only candidate-to-signal binding; no research callback can issue orders.

## Tab 3 → Tab 4 strategy signal pipelines (0.2.0)

All **83 selectable analytical methods** now have an explicit, versioned research-entry policy. Enable a method in **Tab 3 → Strategy and Recipe Library**. **Tab 4 → Signal Queue → Strategy signals** lists every method for the chosen pair/frame, including disabled, missing-data, no-setup, stale, expired, invalidated and blocked states. **Signals only** shows observed triggers; **Ready to bind** shows those currently passing this policy's source/price checks. Enablement alone never fabricates a signal.

- These are **new, disclosed Limit-research compositions**, not a claim that every original indicator or context study intrinsically defines an entry. Directional-event methods use their actual current event and a trigger-body retracement; level studies require a separately observed response to a level frozen before the trigger bar opens. The per-method detail explains the trigger. The existing separately qualified D1/H4 Order Block workflow remains intact and is not silently applied to other methods.
- Common qualification requires the selected authenticated namespace, current enabled method and parameter/projection identity, unresolved-gap refusal, native grid, fresh independently timestamped bid/ask, a pending-Limit entry, intact invalidation, an observed unconsumed opposing pivot/objective, at least 1R after the observed spread and a spread no greater than three native pips. This is gross research geometry, not monetary risk sizing, fee accounting or profitability certification. Missing original executed quantity, documented aggressors, native depth, schedule coverage or published positioning remains **Data unavailable**, never a substitute input.
- Price objectives come only from available same-source confirmed pivots on the signal frame/D1/W1, or the method's declared original objective. No arbitrary target, success probability or synthesized source is added. The maximum lifetime is **14,400 seconds** from the original event/confirmation, shortened by source expiry. Late backfill, re-enabling and recalculation cannot renew it. An observed invalidation/objective crossing remains terminal for that setup.
- Select a ready row, review the disclosed research policy, enter explicit native-valid units and choose **Bind local proposal**. This produces a local queued proposal and opens the separate **Issue queue**; it sends no broker request. The existing deliberate human **Issue** action and execution preflight remain necessary. The core rechecks source, switches, freshness, profile, geometry and lineage at binding and again at Issue. No automatic sizing, order submission or broker SL/TP is introduced.
- All six active pairs and W1/D1/H4/H1 retain the same 1,992 analytical identities. The four workspaces and 42 stable backend identities are unchanged. Context studies remain context until their disclosed additional trigger occurs. Synthetic deterministic acceptance scenarios remain explicitly labelled; they are not connected-market setups, fills or profitable-edge evidence.

### Historical research scope

Open **Strategy Research → Backtesting and Walk Forward**, select a replay run/dataset (or use **Inspect in Research** from a chart), choose a marker profile, stop-distance basis-point axis, target-R axis, maximum holding bars, training/test windows and explicit model roundtrip cost. **Run backtest + walk-forward** saves an immutable study; **View report** shows baseline trades, training-selected OOS folds, ambiguity, drawdown and the full technical result. Saved studies can be reopened from the dataset selector and survive restart.

- The first configuration is the baseline; it is not an ex-post chosen winner. Walk-forward selection uses only resolved training R, with deterministic ties. Test periods are disjoint; training payoffs crossing the boundary remain unresolved. Neither ambiguous intrabar stop/target ordering nor an unfinished trade is counted as a win.
- **As observed** uses actual recorded availability, including late backfill receipt times. It can correctly produce no causal entries. **Historical close assumption** is a separately selected simulation clock for historical candle research, using first-observed revisions. It does not modify source observations or establish that an opportunity was observed/tradeable in real time. Both the original dataset hash and model-input hash are retained.
- This is an explicit next-observed-open, fixed-basis-point stop, target-R and time-exit model. Gap fills use the original bar open. Cost bps is a modelling input, not known broker costs; zero means gross, not net profit. Actual bid/ask/tick fill ordering is not reconstructed from OHLC.
- The historical marker-study selector supports **14 self-contained closed-price profiles**. The full **83 analytical projection profiles** remain coded and available elsewhere; contextual/supplemental profiles are not silently converted into trading systems or fed invented historical inputs. No study can publish a live signal, bind a candidate, select an account or call a broker.
- Limits: one pair/timeframe and 2–2,000 original revisions, up to 64 stop/target configurations and a bounded work/output budget. Insufficient history is reported, not made into an OOS or profitability claim.

## Release acceptance boundaries

The controlling product is the six-pair, four-workspace signal/research platform: 42 stable backend contracts (10/10/13/9), 83 public analytical profiles, one deliberately human **Issue** edge, and source-owned freshness/recovery. NZDUSD is inactive with historical records preserved. Autonomous exit management, consolidated FX full books, general FIX entitlement and profitable-edge certification are not release promises.

Final closure evidence is recorded in `.runtime/program-closure-v20/acceptance-matrix.json` and its manifest/readback. The matrix distinguishes software/engineering controls, original-data native observation, the bounded historical demo Issue/cancel proof, modelled historical studies, operational measurements and optional exclusions. A historical real broker proof is never relabelled as a new order, and a synthetic workflow control is never relabelled native strategy qualification.

## CPU parallelism

Normal Desktop startup defaults to `--compute-workers auto`. The core detects its CPU affinity, cgroup CPU quota and available memory, reserves one CPU scheduling slot where possible, and starts pure projection processes only when enabled methods have work. On a host exposing 16 unquota-limited logical CPUs this currently permits up to 15 workers, not a requirement to keep 15 cores busy. The workload is bounded to the six-pair/four-frame cohort; idle, empty, fixture and headless-check startup do not spawn projection workers.

`--compute-workers 1` retains deterministic serial execution; a positive integer sets a lower ceiling and is clamped to the detected safe capacity. No host CPU affinity or system quota is modified. **Manage → cTrader connection** displays active processes, the ceiling, queued/coalesced lanes and any worker failure. Startup capacity is a ceiling, not a benchmark speedup or a permanent reservation of host CPUs.

Only the shipped pure public-projection math is sent to spawned processes. Runtime/account state, SQLite writes, sensor/recipe publication, source admission, candidate qualification and every broker operation remain with their existing owners. Latest-only queued snapshots replace superseded work; results are source/epoch/version-bound and rechecked for withdrawal, switches and expiry before owner-thread commit. Custom analytical extensions remain serial. Closing the runtime cancels queued work and joins the processes. Historical study execution remains serial and bounded; this change does not claim that every application task is parallel.

## cTrader browser sign-in and saved sessions

### Chart controls and weekend behavior

The chart is source/account-bound and never fills an empty history with invented candles. Visible **− / +**, **Latest**, **Fit** and **Candles / OHLC / Line / Dot** controls complement pointer-anchored zoom, two-axis drag panning and price/time-axis dragging. **Right-click → Mouse wheel** selects Zoom or Scroll; Ctrl+wheel always zooms. Middle-click toggles crosshair. Left/Right moves two candles; Page Up/Down pans a window; Home/End selects oldest/latest; +/− zooms; Alt+1/2/3/4 selects OHLC/Candles/Line/Dot. Up/Down cycles the existing W1/D1/H4/H1 views (or changes Overview's context), never creates extra view identities. Drag the right price scale to rescale; double-click it or select **Tools → Auto price scale** to reset. Panning into history freezes the inspected right-edge candle when new observations arrive; **Latest** returns to following. Blank chart space is not misreported as the nearest candle.

**Tools → Draw lines / text** offers horizontal levels, vertical time markers, Trend, Ray, Fibonacci retracements and plain-text notes. **Draw shapes** adds rectangles, ellipses and bounding-box triangles. Click/drag to draw, then use **Pan / inspect** to move an object or its handles. Shapes have corner and edge resize handles; filled interiors can be selected when that preference is enabled. **Select objects** drag-selects multiple objects; Ctrl adds to a selection, Ctrl+click toggles membership, and Ctrl+drag duplicates before moving. Drawing can extend into blank chart space without creating a candle or making an OHLC inspection available there. Outside loaded bars, annotation time uses nominal timeframe spacing, not a predicted broker trading calendar.

Double-click an object or press Enter for **Object properties**: name, exact UTC/price anchors, colour, line style/width, fill/opacity, label/text size, bold text, line extension, per-object snapping and editable Fibonacci percentages/prices. Trend/ray view angles are optional screen-space measurements and change with zoom. Untouched coordinates and styles keep their original precision. Invalid edits apply nothing; a source change closes the editor, and a concurrent object change refuses stale edits. Apply saves locally; Cancel discards only edits made since the last Apply.

**Objects** (Ctrl+D) filters/selects drawings and exposes properties, duplication, bulk hide/lock, arbitrary RGB colour, layering, exact level price, find, delete and undo/redo. **Style…** applies only the explicitly checked appearance fields to the selection, preserving each object's names, notes, coordinates and flags. The same actions are reachable through **Tools → Object actions** and right-click. Ctrl+C/X/V copies/cuts/pastes only within the exact chart source/frame; Ctrl+Shift+D duplicates, Del deletes, Ctrl+Z undoes, Ctrl+Y or Ctrl+Shift+Z redoes, and Escape cancels an active gesture. A drag or bulk style update is one undo step. Alt+arrows nudge by configured bar/pip steps; Shift+Alt uses ten steps. Shift or Alt during drawing temporarily bypasses OHLC snapping; snapping never borrows prices from blank space.

**Right-click the chart → Settings → Chart colours…** opens all 30 chart colour roles, with arbitrary RGB/hex values for candles, wicks, borders, axes, text, grid, crosshair, studies, volume, projections and rulers. **Left-click an object, then right-click → Object settings / colours…** edits that selected drawing's outline, fill, text and label background (where applicable). Fill/text can follow the outline, and label backgrounds can follow the chart, or each can use its own colour. Apply commits; Cancel discards only unapplied changes. Selection uses a forgiving **14 px** default tolerance, includes visible labels and enabled filled interiors, and prefers the nearest outline rather than a covering filled shape. **Right-click → Settings → Object selection…** adjusts tolerance within 4–32 px. Locked objects remain selectable without accidental movement; hidden drawings are not hit targets.

**Settings** groups appearance, colours, axes/rulers, navigation, visibility and shortcut help. It includes SFM navy/light/high-contrast chart presets, independent bull/bear fills, candle/wick/line/dot sizes, axis text size, horizontal/vertical grid switches and styles, crosshair style/width, tick-volume height, price padding, right margin, wheel behavior, one-shot drawing, hit tolerance and nudge steps. Visibility switches separately control local drawings, drawing labels, title, study legend, forming observations, close/bid/ask lines and read-only research/broker overlays. **Drawing defaults…** edits future styles per drawing type without creating an object; current objects remain unchanged. Resets are staged until Apply.

**Measure** offers a combined **Range ruler**, dedicated **Time ruler** and dedicated **Price ruler**. Drag in the chart, or choose the corresponding ruler and drag directly on its axis. **Shift+drag the bottom time axis** measures only time; **Shift+drag the right price axis** measures only price. Ordinary axis drags still zoom/scale; a ruler gesture never changes the viewport or creates a drawing. **Esc** or the axis context menu clears the temporary measurement. Time measurements count observed candle intervals and show actual UTC elapsed time, including gaps, not an invented trading calendar. Price measurements show signed pips, percentage and exact endpoint prices. The time-only ruler supplies no calculator-price scenario. Endpoints must belong to loaded source-bound bars; blank future space is not measured as fabricated candles.

**Settings → Axes / rulers** controls axis text size, price/time tick spacing, axis rails, minor ticks, hover highlighting, measurement colour, guides and the persistent readout. Choose **Adaptive UTC**, **ISO date + time** or **Date only**, plus any of four readout corners; hide the readout if it obscures a compact chart. Labels adapt to the actual font and plot width, with separate time/price gutters, connected endpoint badges and a highlighted measured time span. Right-click either axis for its scale reset, measurement and settings actions. Display preferences save locally per account/source/pair/timeframe; rulers do not persist and do not create observations, signals or broker commands.

Local drawings and preferences save through the existing shared core to SQLite with payload limits and version-conflict checks; **Notes** offers explicit save/reload and archived-source inspection. Notes remain account/source epoch/symbol/frame scoped. Reconnection archives old-epoch annotations instead of transplanting them; safe display preferences may carry forward within the same account/pair/frame. Undo stacks, pan offsets and temporary rulers remain in memory. No annotation, copy/paste, property edit or setting becomes a research signal, cTrader object or order instruction.

**Tools** or **right-click → Viewing options** independently shows bid and ask lines. Ctrl+B toggles Bid. The Windows guide's Ctrl+K Ask shortcut is intentionally not copied because SFM already reserves Ctrl+K for pair navigation. Axis badges use **C** for the visible completed candle close, **B** for bid and **A** for ask. Equal prices combine labels; collision-displaced badges retain value ordering and connectors to the exact price coordinate. Weekend quote lines remain labelled as snapshots by the quote strip, not as live prices.

**Studies** provides cached shared-backend SMA(20) and EMA(50) of closed bid candles, with explicit warm-up requirements. These display studies do not create strategy signals. **Tools** contains grid/crosshair/tick-volume switches, date navigation within loaded history and horizontal levels. **Measure** contains the pip/percent/bar/time rulers (**Shift+drag** also measures). Volume is the native bar's tick count, not exchange volume; absent volume remains unavailable. A separate dashed forming observation may display during an open session; it is not counted as a completed candle or used to warm up closed-bar studies. **Export** writes observed closed-candle CSV or a chart PNG after a local destination is chosen. Drawings/exports never issue broker orders.

Authentication, chart history, session schedule and quote time are distinct. **BROKER DATA** is provenance, not freshness. On a broker-scheduled closure the chart shows **Market closed**, retains readable history and labels old prices as **last market snapshot**; the actual provider time is available in the quote tooltip and is never refreshed by reconnecting. The scheduled reopening comes from the selected account's current native symbol calendar, not a hard-coded Friday/Sunday assumption. It is not a guarantee against holiday/maintenance changes. A fresh-open-market quote gate is never relaxed by this closed-market display.

The weekend reconnect repair compares quote ordering only within the same source epoch: a new connection's official last-price snapshot may be older than the prior connection's final streamed price without invalidating the authenticated account. Same-epoch out-of-order updates remain rejected. History pagination stops at the requested lower bound even when a counted native response includes older data; page/nonprogress budgets prevent walking unrelated years of history.

The shared connector acknowledges spot subscriptions and completes each bounded history bootstrap before subscribing to that symbol/period's native live trendbars. Native `ProtoOASpotEvent.trendbar` closes flow into the same scoped market store, chart queries, studies and downstream consumers. Duplicate closes are idempotent; corrections advance immutable availability/revision. Wrong account/epoch, unsupported periods, future/incomplete bars and older native updates do not replace accepted closed candles. Bid ticks still supply explicitly partial forming observations but do not compete with the native finalizer. Subscription ACTIVE means the server acknowledged it, not that a closed-market session has delivered a new bar. Failures stay explicit without blind retries; health tooltips show pending/active/failed counts.

History failure is lane-local, not a global research lock. An in-flight history job defers its affected pair; healthy pairs continue, and a terminally failed frame stays explicitly unavailable instead of borrowing old-epoch bars. Broker DOM has its own acknowledged subscription and does not wait for all 24 candle-history lanes. Connected research refreshes one ready pair per pump in rotating order so native responses can keep flowing; failed refreshes retain their pending work.

Local SDK command waiting and response waiting have separate bounded clocks: up to 120 seconds before SDK acceptance, then the existing 30-second parent response budget (the SDK also retains its own timeout). SDK acceptance is not a wire-send or broker-acknowledgement claim. These transport budgets do not extend quote/book freshness, change market timestamps, retry failed history or relax unknown-order safeguards. The feed dialog continues to show **history incomplete** when an individual lane fails. Source and external-installed native checks exercise a withheld genuine history response, healthy chart delivery and a fully recovered new connection; see `.runtime/feed-bootstrap-isolation-v5/final-evidence.json`.

The cTrader interaction research, official image provenance, implemented mechanics, platform-specific shortcut conflicts and deferred parity features are recorded in the dated `PROGRESS.md` entry. This is an adaptation of published chart documentation, not a claim of complete cTrader feature or pixel-level parity. Multi/free-chart layouts, cloud templates, full indicator catalogue, advanced drawing families, alerts, QuickTrade and in-chart order mutation remain unimplemented.
